# Glossary

Terms used across BACO documentation.

| Term | Definition |
|------|------------|
| **Citation verification** | Gate that validates finding citations against the source tree to ensure reported vulnerabilities reference actual code. |
| **Confidence score** | A 0.0–1.0 value representing the likelihood that a finding is a true positive vulnerability. |
| **Cross-file analysis** | Pipeline phase that traces data flow across multiple source files to detect vulnerabilities requiring context beyond a single file. |
| **CPG** | Code Property Graph — a multi-layered graph representation of source code generated by Joern for cross-file analysis. |
| **CWE** | Common Weakness Enumeration — a community-developed list of software and hardware weakness types. |
| **Evidence gate** | Minimum confidence threshold a finding must meet to be included in the final report. |
| **Finding** | A detected vulnerability represented by the `VulnerabilityFinding` struct, containing location, severity, and confidence data. |
| **Hunt prompts** | Domain-specific prompt modules sent to LLMs to guide vulnerability discovery during verification phases. |
| **Joern** | Code Property Graph engine used for cross-file analysis and data flow tracing in BACO's pipeline. |
| **MoE** | Mixture of Experts — the router architecture that directs findings to specialized LLM models based on vulnerability type. |
| **Org-context profile** | Organizational policy configuration injected into prompts to tailor scanning behavior and reporting to specific compliance needs. |
| **Phase** | A discrete step in BACO's 23-phase pipeline, each responsible for a specific analysis or verification task. |
| **PhaseGraph** | Data-driven pipeline orchestration structure that manages phase execution order and dependencies. |
| **PoC** | Proof of Concept — a minimal exploit demonstrating that a reported vulnerability is actionable and exploitable. |
| **Prior runs** | Cross-run findings history used to track previously detected vulnerabilities and support skip directives for unchanged code. |
| **SAST** | Static Application Security Testing — analyzing source code for vulnerabilities without executing the program. |
| **SARIF** | Static Analysis Results Interchange Format — a standard JSON format for sharing analysis results between tools. |
| **Semgrep** | Static analysis tool used for pattern-based detection of common vulnerability patterns in BACO's initial scan phases. |
| **Triage** | The process of prioritizing findings for human review based on severity, confidence, and organizational risk tolerance. |
| **Verification tier** | Confidence classification grouping findings into supported, probable, or speculative categories based on evidence strength. |
| **CPG** | Code Property Graph — a multi-layered graph representation of source code generated by Joern for cross-file analysis. |
